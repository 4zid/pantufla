# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

Pantufla is the site of a small web studio: a one-page home plus `/reunion`, the `/proyectos` listing, project detail pages and an embedded Sanity Studio. Next.js 16 (App Router, Turbopack), React 19, Tailwind v4, Sanity, GSAP, Lenis, Resend, Vercel. Code comments, copy and most identifiers are in Spanish (Argentine voseo); comments explain the _why_ at length and new code should keep that style.

## Commands

```bash
npm run dev          # development server
npm run build        # production build
npm run start        # serve the build (PORT=3350 npm run start)
npm run typecheck    # tsc --noEmit
npx prettier --write <files>   # formatting (Prettier defaults, no config file)
```

- There is no test suite and no linter: `npm run lint` calls `next lint`, which Next 16 no longer ships, and there is no ESLint config. Verify changes with `npm run typecheck`, `npm run build`, and by looking at the page in a browser (Playwright + Chromium are available in the cloud environment).
- Build output is long: redirect it to a file instead of piping into `head`, which kills the build. Sanity fetch errors during a build (403, offline) are expected and harmless; every query falls back to local content.
- For a clean check: `rm -rf .next && npm run build && PORT=3350 npm run start`.

## Branches and deploys

- `main` is production (Vercel's production branch and the repo's default branch). **Every push to it goes live** at www.pantufla.design.
- `staging` is the preview at `pantufla-git-staging-kalada.vercel.app` (behind Vercel login), for trying designs before they ship.
- Work goes on a branch cut from `main`: `feat/<topic>` for new things, `fix/<topic>` for fixes (lowercase, hyphens). Merge it into `staging` to preview, then into `main` through a pull request once approved, and delete it. Merge `main` back into `staging` whenever `main` gets something `staging` lacks. Do not commit straight to `main` unless the user asks for it.
- Non-production deployments (`VERCEL_ENV=preview`) render `noindex` and a closed `robots.txt` via `lib/entorno.ts`.
- Vercel does not build a branch whose head commit was already built on another branch; it needs its own commit.
- Pages that were removed (`/contacto`, `/notas`) redirect in `next.config.ts`. The `/proyectos` listing was redirected too and is a page again.

## Architecture

### Routing and languages

Every page lives under `app/[locale]`. Spanish is served at the root and English under `/en`: `middleware.ts` rewrites unprefixed paths to `/es/...`, redirects any public `/es/...` to the root, and picks a language for first visits from the Vercel country header, then `Accept-Language`, with the language cookie always winning. Crawlers and link-preview bots (`userAgent(request).isBot`) skip that detection and get each URL in its own language with no redirect: Googlebot crawls from the US, and the redirect to `/en` kept it from ever reading a Spanish page. Route segments stay in Spanish in both languages. Hrefs in copy are written unprefixed and localized with `localeHref` / `useHref`.

The `(site)` route group adds the header and footer through `components/site-chrome.tsx`; `/studio` sits outside it and mounts Sanity Studio (`sanity.config.ts`, basePath `/studio`).

### Content comes in three layers

1. **Text.** `content/copy.ts` declares the `SiteCopy` type explicitly, so a new field breaks compilation until both `content/copy.es.ts` and `content/copy.en.ts` have it. Those files are the fallback; the editable version is one Sanity `siteCopy` document per language (fixed ids `siteCopy.es` / `siteCopy.en`), deep-merged over the local copy in `content/get-copy.ts`, where null fields are skipped. Arrays are not merged: a loaded array (nav, FAQ items, title segments, plans) replaces the local one whole, so editing one in the repo changes nothing in production until the Sanity document is patched and published too. Adding a copy field means updating the type, both locale files, and `sanity/schemas/site-copy.ts`.
2. **Design data.** Colors, icons, step numbers and bento grid placement live in `content/site.ts`, keyed by the same ids as the copy, and are joined to the text in `content/resolve.ts`. Text never carries colors.
3. **Sections.** `content/sections.ts` (`SECCIONES`) is the single list of home sections: it sets their order, the on/off switches in the Studio, and which anchors die with each one. The Sanity `siteSections` document stores `<id>` booleans and `<id>Fondo` (`claro` / `oscuro`); a missing value means the factory default (on, except sections marked `apagada`, currently the stack). `app/[locale]/(site)/page.tsx` maps each id to a builder that receives its `surface`, and `pruneHrefs` rewrites links that point at a disabled section. When testimonials and the clients map are both on, the map renders inside the testimonials section, above the testimonials (`ClientsMap embedded`, passed as `children`), with the testimonials surface; neither shows a visible title (sr-only headings only).

`sanityFetch(query, params, fallback, tags)` in `sanity/client.ts` never throws; it returns the fallback. Projects and testimonials fall back to `content/fallback-content.ts` while the CMS is empty; that placeholder content is intentional. Cache tags are expired by the `/api/revalidate` webhook. The other API routes are `/api/brief` (form → Sanity + Resend), `/api/lugar` (the pass forms: email from the hero, name + email from the banner → a `lugar` document, one per email, + Resend) and `/api/reunion` (Cal.com webhook). The hero gallery has no list of its own: it is built from each project's `pantallas` field (Studio «Pantallas para la portada»: frameless screenshots, each marked desktop or mobile), in project order, grouped so a stacked column never mixes two projects, and each column takes the width its screenshots' proportions ask for (`hero-galeria.tsx`). While no project has screens, or Sanity does not answer, the same screens from `content/hero-galeria.ts` (`public/hero/pantallas`) are used, all or nothing.

A project's written case (`body`, «Caso completo» in the Studio) decides whether its page exists publicly: with a case, the home row links «Leer el caso», the page is in the sitemap and indexable; without one, the page renders but is `noindex`, left out of the sitemap and of the home. The local copies of the written cases are in `content/casos.ts`. `lib/calendario.ts` says whether `NEXT_PUBLIC_CAL_LINK` is set; while it is not, CTAs that promise booking offer the email instead.

### One page background, two themes

Sections never paint a background. The light page background is white (it was a lilac mist, `#eaedf8`; the surface is still called `mist`), so anything that used to stand out by being white needs a hairline border or `bg-paper-alt`. They declare `data-surface="mist" | "deep"`, and `components/theme-scroll.tsx` sets `data-tema="oscuro"` on `<html>` while a deep section covers the band at 45–55% of the viewport. All theme colors are custom properties registered with `@property` in `app/globals.css`, so they transition: surfaces fade in 600 ms, while ink (and `on-ink`, the text color for anything on a `bg-ink` fill) steps at 300 ms, the point where dark and light ink read equally; a fade crossing a fade always has a gray-on-gray frame. Use `text-on-ink` on `bg-ink`, never `text-paper` or white. While a change runs, `theme-scroll.tsx` sets `data-tema-cambiando` on `<html>` and element-level color transitions (`.transition-colors`, `.sigue-tema`) are suspended so they track the tokens frame by frame. The dark theme also sets `color-scheme: dark`, and `theme-scroll.tsx` swaps the `theme-color` meta between the two `--page-bg` values. Tailwind utilities resolve to those variables, which is what makes components theme-agnostic: use tokens, not hardcoded hex, for anything that must follow the theme.

### Motion

- GSAP and ScrollTrigger are registered through `lib/motion.ts` (`registerGsap`, `START`). Lenis (`components/smooth-scroll.tsx`) drives ScrollTrigger, and handles same-page anchor clicks in the capture phase so Next's `Link` does not jump.
- **Initial states of entrance animations live in CSS**, under `.motion-ready` (added by an inline script in `app/[locale]/layout.tsx`), and tweens are `gsap.to(..., { immediateRender: false, scrollTrigger })`. Do not use `from` / `fromTo` for scroll entrances: they write inline styles at creation, and across dozens of components that became a chain of forced reflows during hydration. A new animated `data-*` hook needs its initial state and a reduced-motion override in `globals.css`.
- Every animation runs inside `gsap.matchMedia()` with a reduced-motion branch. With reduced motion or with JavaScript off, everything must be visible.
- The hero entrance is pure CSS (`data-entra`, `SplitHeading immediate`) so the LCP does not wait for JavaScript.
- The hero (`components/sections/hero.tsx`) is a left-aligned text column (availability pill, title, lead, CTAs) with the Pantufla pass on the right, its email form below it (`components/pase/pase-formulario.tsx`, posted to `/api/lugar`), and the masonry screen gallery (`hero-galeria.tsx`) below, full width. The banner's form (`conNombre`, `sobreTinta`) also asks for a name. The form state is shared by both forms and the 3D pass through `lib/pase.ts` (a `useSyncExternalStore` store, remembered in localStorage as JSON; a bare email string from before still reads); once reserved, the pass prints the name (or the email) on its face.
- The pass is a 3D paper (`components/pase/pase-3d.ts`, Three.js, imported only after the capability check): one fixed full-viewport canvas (`pase-escena.tsx`, `z-30`, no pointer events) draws a 13 × 20 Verlet cloth with stretch, shear and bend springs, each point tied to its target by a spring that is stiff in the centre and loose at the edges, plus air drag on the face and a little weight in flight. The page only holds the slots (`[data-pase-lugar="hero" | "banner"]`, `pase-lugar.tsx`) with a fallback image; `[data-pase-3d]` on `<html>` hides those images while the 3D runs. One world unit is one CSS px and the camera makes the z = 0 plane real size, so a flat pass lands exactly on its slot. With both slots on (desktop/tablet), it peels off the hero slot when that slot's centre reaches 15% of the viewport, shrinks to 0.34 (it was 0.42 and the user found it annoying while scrolling), crosses the page in the lower third turning over, one round trip every four screens (the back shows mid-crossing) and lands lying down in the banner's slot, halfway down the home (`components/sections/lugar.tsx`, after Capacidades: the user found a flight across the whole page annoying). A slot wider than tall is a lying-down pass: the 3D scales it from the slot's height and rotates it a quarter turn. `GIROS` (`pase-lugar.tsx`) are CSS degrees (clockwise positive) shared by the fallback image and the 3D, which flips the sign because its y axis points up. The banner is centered and stacked (title, hole, then the name + email form in one row), kept short with the `compacto` rhythm and tight gaps; it went two columns once and the user asked for the centered one back, just shorter. It is built around that slot: an ink card with a strip of dashed coupons and a cut-out hole (page colour) with the pass's exact corners and two tabs that fill the stub's notches (measured from the texture), so the landed pass reads as the missing piece. Focus inside a pass zone (`[data-pase-zona]`) keeps it docked there. On phones it stays in whichever slot is visible. Everything is a function of scroll and pointer: when the paper settles the loop sleeps. It never runs under reduced motion, nor on software WebGL (renderer name check, like the old ribbon); `?pase3d` forces it for headless tests, where the lighting can also be overridden from the URL (`env`, `luz`, `brillo`, `iris`). Since r163, environment intensity is `scene.environmentIntensity`, not the material's `envMapIntensity`. The textures (`public/pase`: face es/en, back, and an R/G/B map for iridescence/roughness/metalness) are drawn in HTML by `scripts/generar-pase.mjs`; the pass text is part of that drawing, not of the Studio. The pass is deliberately sober (the user asked for fewer colours and a premium feel): ivory paper, one ink, Newsreader italic mixed with Schibsted, a black foil seal, a black back, and a champagne/pearl foil edge that follows the notches and the lanyard slot, which is the only colour and is metallic and slightly iridescent in the 3D. The banner echoes it: ink, with champagne only on the cut line, the scissors and the ticks.
- «Dónde trabajamos» (`components/sections/clients-map.tsx`) is a black-and-white globe (`globo.tsx` + `globo-3d.ts`, Three.js, imported only when the section nears the viewport and after the same capability check as the pass, `lib/webgl.ts`; `?globo3d` forces it). The sphere carries a mask texture drawn at runtime from `content/globo-datos.ts` (Natural Earth 110m land and the marked countries, equirectangular 2048 × 1024, generated by `scripts/generar-globo.mjs`): land in R, countries in G, graticule in B, coloured in the shader with theme tokens (`paper-alt`, `line-strong`, `ink`, `line`) re-read while `data-tema` transitions. On top of that the shader adds a holographic finish (a pearl sheen in the pass's foil palette that depends on view angle and surface position, so it slides as the globe turns, stronger at the limb) and screen-space grain added after the sRGB conversion (`ruido`; `?globo3d=limpio` turns it off, which is what the fallback generator uses, and the fallback gets a CSS grain overlay instead because noise does not compress). The section is a poster: the `clientsMap.backdrop` word («Worldwide», uppercase via CSS) set huge in Schibsted Black behind the globe (14vw so it never exceeds the viewport; above the globe on phones, where the globe would hide it) (the user asked for no country list below; the names are only on the markers, plus an sr-only list). It spins west to east (one turn per 70 s), pauses like a rail (it sits in `RielPausable`; hover, focus, tap, keyboard button), sleeps offscreen. Markers with the names are HTML moved per frame with `lib/globo.ts`, the same projection the static fallback uses (`public/globo/globo.webp`, shot from the 3D by `scripts/generar-globo-imagen.mjs`; inverted by CSS in the dark theme). Reduced motion or no hardware WebGL keep the fallback. The countries are `clients` in `content/site.ts` (Argentina, Colombia, United States, Spain, Denmark/Copenhagen); a new one needs the generator, `content/countries.ts` and a new fallback image. It replaced a flat SVG map with arcs from Buenos Aires.
- Anything that moves on its own must be stoppable. Tickers are wrapped in `RielPausable` (`components/ui/riel-pausable.tsx`): they pause on hover, focus-within, a touch tap, and a keyboard-only button (`header.pauseMotion` / `resumeMotion` in the copy). Testimonials no longer rotate: they are a row of four square cells (`lg:aspect-square` with `w-full`, since a grid item with an aspect ratio otherwise takes its width from its height and overlaps the next cell), no outer border or radius, 1 px lines between them, number badge, company, quote and name; one cell is ink and follows the mouse. The hero gallery and the client-logo strip (logos only, full width) are `RielPausable` tickers too.
- The header (`components/site-header.tsx`) has no bar at the top of the page: logo, a glass pill for the nav and the buttons float with the hero's margin (96 px at 1440, max width 1440). Its row is a three-column grid so the nav stays centered. It compacts after 40 px and hides while scrolling down, but stays visible during a programmatic jump (nav anchors; `lib/scroll.ts` carries the signal from `smooth-scroll.tsx`), with keyboard focus inside, and with the mobile menu open. It highlights the section crossing 40% of the viewport. The mobile menu stops Lenis through `lib/scroll.ts`, makes the page behind `inert`, closes on Escape and when the viewport reaches `md`.
- The projects section (`components/sections/work.tsx`) is a 2 × 2 grid of the four projects marked «Destacado en la home» (`featured`, in `order`; the first four if none is marked), plus a «Ver todos los proyectos» link to `/proyectos`, which lists every project with the same card (`components/ui/proyecto-tarjeta.tsx`). Each card is a minimal mockup on a gray plane: a browser window with the site's domain and, overlapping it, a phone, both built from the project's `pantallas` (`content/mockup.ts`: the desktop screen closest to 16:10 and the first mobile one; local `content/hero-galeria.ts` screens when Sanity is out). Without screens the window shows the project name; covers are never used there (they are composed mockups or illustrations). The whole card links to the case when written, else to the live site. It was a sphere list with a sticky heading and before that a pinned wheel-driven stepper; the user found the stepper painful, so do not reintroduce scroll hijacking there.

### Styling

- Tokens are in `app/globals.css` (`@theme`). `cn()` in `lib/cn.ts` is a plain join, not tailwind-merge: when two utilities conflict, CSS order wins, not argument order.
- Lots of whitespace, restrained type (the user asked for it): `.shell` is 72rem with padding growing to 3rem (192 px margins at 1440), headings are a step smaller (h2 42 px, display 60 px, hero title 68 px at 1440), and section padding comes from `Section`'s named `ritmo` (`normal`, `compacto` for pricing and FAQ, `amplio` for the process), not from a `py-*` className, which would fight the default under `cn()`.
- Four brand colors (aqua, rosa, verde, miel), each with `-soft`, base and `-deep`. The base shade never carries small text on a light background. `lib/tones.ts` maps tones to full class names because Tailwind cannot build class names at runtime.
- The font is a self-hosted subset of Schibsted Grotesk (weights 400–600, Latin) at `public/fonts/schibsted-grotesk-latin-v1.woff2`, preloaded by hand in the locale layout and declared in `globals.css` with metric-adjusted fallbacks. `next/font` did not emit its preload in this build. Weights above 600 do not exist, except a 3 KB uppercase-only Black (900) subset, `public/fonts/schibsted-grotesk-black-mayusculas-v1.woff2` (from `@fontsource/schibsted-grotesk`, cut with fonttools), declared in the same family with a `unicode-range` and used only by the globe's backdrop word; if a file changes, bump the `-vN` in its name, since `next.config.ts` serves it with an immutable cache header.
- A second family, Newsreader italic (`font-serif`, `public/fonts/newsreader-italic-latin-v1.woff2`, 19 KB: instanced at weight 400 and optical size 72, Latin subset), is for the `serif` mark of `SplitHeading` (the two accent words of the hero title, in the same ink as the rest) and the pass: it is baked into the pass textures, and the 3D pass draws the reserved name with it on its canvas, relying on the hero having loaded it. Nothing else on the page uses it. The hero preloads it with `preload()` from `react-dom`, so other pages never download it. The serif words carry their own `leading-[0.712]` so their baseline matches the Schibsted words inside the 0.98 title; with another line height that number has to be recomputed (see `split-heading.tsx`).
- `experimental.inlineCss` is on: CSS ships inside the HTML.
- Client logos (`public/logos/clientes`) are black on transparent and drawn as CSS masks filled with `currentColor` (`.logo-cliente`), so they follow the theme. Each entry in `socialProof.brands` (`content/site.ts`) carries its width/height `proporcion`; the strip gives every logo the same area, and `escala` nudges one that still reads light. A client without a file falls back to its name as text.

### SEO

Canonical, hreflang, sitemap and JSON-LD all derive from `siteUrl` (`lib/site-url.ts`); the structured-data graph is built in `lib/schema.ts`. `app/llms.txt` describes the studio for answer engines.

## Design skills vs. project decisions

Two third-party skills live in `.claude/skills` (sources and hashes in `skills-lock.json`, update with `npx skills update`): `design-taste-frontend` (from `Leonxlnx/taste-skill`), a general guide for new design work, and `web-design-guidelines` (from `vercel-labs/agent-skills`), a UI audit that fetches Vercel's rule list at run time. Where either conflicts with this site, the site's existing decisions win; do not "fix" these to satisfy a skill:

- Motion is GSAP + ScrollTrigger + Lenis, not Motion/Framer.
- The page switches theme on scroll (Proceso, Proyectos and the form default to dark).
- The hero is text on the left (availability pill, title with two serif italic words, lead, CTAs), the sober 3D paper pass on the right (ivory, one ink, serif + sans, champagne foil edge; with its form below) that flies with the scroll and lands lying down in the mid-page banner, and the masonry screen gallery below. It replaced the Claude Design hero (WebGL ribbon and project carousel) on purpose, which had replaced the old dashboard hero.
- Icons (`components/ui/icons.tsx`), the brand mark and the bento vignettes are hand-made SVG/HTML.
- Section labels use the `Tag` pill on most sections.
- Client logos in the social-proof strip are one color (the theme ink), not their brand colors.
- Passive `scroll` listeners in `site-header.tsx` and `theme-scroll.tsx` are intentional.
- First-visit language comes from the Vercel country header before `Accept-Language` (`middleware.ts`), on purpose.
- Copy is Spanish sentence case; English Title Case rules do not apply.

Changing any of these is a design decision for the user, not a cleanup.
